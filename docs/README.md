## 文档清单

| 文档 | 回答什么问题 | 何时更新 |
|---|---|---|
| [`需求与设计.md`](./需求与设计.md) | 为什么做这个项目、目标形态是什么、技术选型理由、数据源/数据模型约定 | 新增数据源、变更架构或技术栈时 |
| [`开发历程.md`](./开发历程.md) | 做过什么、什么时候做的、当时的决策与取舍、还没做的候选 | 每完成一批改动追加一行 |

| [`功能验收清单.md`](./功能验收清单.md) | 每个页面/控件/接口/流程的预期行为与可勾选验收项（当前唯一"功能真相"） | 改功能时同步 |
| [`项目体检报告.md`](./项目体检报告.md) | 体检发现（死代码/重复/依赖/安全隐患/测试缺口）与处理顺序 | 每次体检追加一节 |

阅读顺序建议：**README → 需求与设计 → 功能验收清单**（要动手改代码时看最后一份）。

## 边界约定

- **`README.md`** 只放"能跑起来"所需的命令、配置项、部署方式；不写历史。
- **`AGENTS.md` / `CLAUDE.md`（项目根）** 是给 AI 编程助手的工程约定，属工具配置而非项目文档，故留在根目录不迁入此处，也不与 `README.md` 合并。
- 本目录文档不写"当前代码有多少行/有哪些函数"——这类信息会立刻过期，需要时直接看代码或用 [`功能验收清单.md`](./功能验收清单.md) §1 的全景表。
