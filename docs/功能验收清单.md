## 1. 系统全景

```
浏览器 (5173 或因内网穿透的域名)
   │  axios /api/*  (开发态 vite proxy → 8000；生产态同源)
   ▼
FastAPI (backend/main.py)
   ├── /api/articles /api/sources /api/stats /api/collect /api/agent/chat
   ├── APScheduler（启动即采集一次，之后每 COLLECTION_HOURS=6h）
   └── 静态托管 frontend/dist（存在即挂载，单端口部署）
        │
        ▼
   src/ 采集引擎 NewsEngine
   六源并行 → 跨源去重 → 排序 → LLM 相关性过滤+质量打分
        │                                    │
        ▼                                    ▼
   SQLite (articles / collection_runs / user_profile)   ChromaDB (语义索引)
```

| 层 | 目录 | 职责 |
|---|---|---|
| 采集管线 | `src/`（sources / engine / pipeline / models） | 抓取、去重、排序、LLM 判定，无 Web 依赖 |
| Web 层 | `backend/`（main / routers / scheduler / agent / database / vector_store） | REST、SSE、调度、持久化 |
| 前端 | `frontend/src/`（views / components / stores / api / layouts） | Vue 3 SPA 三栏看板 |

## 3. API 清单

统一前缀 `/api`。若 `.env` 配了 `API_TOKEN`，所有 `/api/*`（OPTIONS 除外）必须带 `X-API-Token`，否则 401。

### API-01 `GET /api/articles` — 按时间窗口取文章

| 项 | 内容 |
|---|---|
| Query | `days` 1–365（默认 7）· `sources` 逗号分隔（默认全部）· `limit` 1–200（默认 20；前端传 50） |
| 响应 | `{"total": int, "articles": Article[]}` |
| Article 字段 | `id, title, url, source, summary, author, published_at, score, tags[], quality?, language` |
| 错误 | 参数越界 → FastAPI 422；无数据 → `total: 0, articles: []` |
| 注意 | `total` = **本次返回条数**（受 limit 截断），不是全库总数 |
| 实测 | `days=1&limit=200` → `total=99`；`days=7&sources=arxiv,github&limit=200` → `total=67`，源只含 github/arxiv ✅ |

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/api/articles?days=1&limit=5"
```

### API-02 `GET /api/sources` — 源列表 + 计数 + 开关态

| 项 | 内容 |
|---|---|
| 响应 | `{"sources":[{name,label,description,category,article_count,enabled}]}` |
| category 枚举 | `tech_community` / `academic` / `chinese_media` |
| 语义 | `enabled` 由 `user_profile.selected_sources` 推导，**空列表 = 全选 = 全部 enabled** |
| 实测 | `hackernews=123, arxiv=179, huggingface_papers=168, rss=79, github=159, csdn=49`，六源全 `true` ✅ |

### API-03 `PUT /api/sources/{name}` — 切换单个源

| 项 | 内容 |
|---|---|
| Body | `{"enabled": true|false}` |
| 响应 | `{"name": str, "enabled": bool, "selected_sources": str[]}` |
| 语义 | 全选态关掉一个 → 存剩余列表；再开回全部 → 规范化为 `[]`（全选态） |
| 错误 | 未知源 `404 {"detail":"未知数据源: xxx"}`；关掉最后一个 `400 {"detail":"至少保留一个数据源"}` |
| 生效范围 | **只影响调度器采集**，不影响 CLI |
| 实测 | 未知源 PUT → 404 ✅ |

### API-04 `GET /api/stats` — 采集统计

| 项 | 内容 |
|---|---|
| Query | `limit` 1–100（默认 10）最近 N 次明细 |
| 响应 | `{"total_runs","total_articles","last_collection_at","runs":[{id,started_at,finished_at,status,total_articles,deduped_count,source_stats[],error}]}` |
| `source_stats[i]` | `{name, fetched, failed, error, elapsed_ms}` |
| 实测 | `runs=71, articles=3773, last=2026-10-29T12:45:08Z`；run#71 `finished/total=58` ✅ |

### API-05 `POST /api/collect` — 手动采集（异步）

| 项 | 内容 |
|---|---|
| 请求体 | 无 |
| 响应 | `202 {"status":"started"}` |
| 行为 | `asyncio.create_task(collect_once())`，与 Agent 的 `trigger_collection` 共用；`_collect_lock` 防并发 |
| 观察方式 | 轮询 `GET /api/stats` / `/api/sources`（前端固定 12s 后轮询一次） |
| 错误 | 采集异常只写日志，接口仍 202 |

### API-06 `POST /api/agent/chat` — Agent 对话（SSE）

| 项 | 内容 |
|---|---|
| Body | `{"message": str(1–4000), "history"?: [{role,content}] ≤20 条且总字符 ≤20000, "interests"?: str[]}` |
| 响应 | `text/event-stream`，`Cache-Control: no-cache`、`X-Accel-Buffering: no` |
| 事件 | `{"type":"tool","name","status":"start"|"done"}` / `{"type":"token","text"}` / `{"type":"done","answer"}` / `{"type":"error","message"}` |
| 错误 | 空消息 → `400 {"detail":"message 不能为空"}`；流内异常 → 发一条 `error` 事件而不是断连 |
| 记忆 | `interests` 缺省读 `user_profile`；`reading_history` 恒由后端把文章 ID 解析成标题注入（不重复推荐） |
| 归档 | `history>12` 时把最早 `len-12` 条压缩进 `conversation_summary`，只把最近 12 条发给 LLM |
| 实测 | 200 + `text/event-stream`；4 个 tool 事件 + 285 token + 1 done；首 token 1.01s，总 4.42s ✅ |

```powershell
# 注意 PowerShell 调用原生 curl 时的引号坑：JSON 里的双引号必须写成 \" 才会传进去
curl.exe -sN -X POST http://127.0.0.1:8000/api/agent/chat `
  -H "Content-Type: application/json" `
  -d '{\"message\":\"总结今天的 AI 热点\"}'
```

## 4. 数据模型与存储

### 4.1 `articles`（SQLite，WAL）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PK | 源内稳定 ID 或 url 哈希；`INSERT OR REPLACE` |
| `title` / `url` / `summary` | TEXT | `summary` 可能为 null（前端归一化为 `''`） |
| `source` | TEXT | 六源之一 |
| `author` / `published_at` | TEXT NULL | ISO 8601 |
| `score` | INTEGER | 源内热度（HN 分数 / GitHub 今日 star / CSDN 阅读量 …） |
| `tags` | TEXT(JSON) | 读写时序列化/反序列化 |
| `quality` | REAL NULL | LLM 质量分 0–100；未评分/NULL 时排序回退 1.0 系数 |
| `language` | TEXT | `en` / `zh` |

### 4.2 `collection_runs`

`id, started_at, finished_at, status(started/finished/failed), total_articles, deduped_count, source_stats(JSON), error`

### 4.3 `user_profile`（单行）

`interests(JSON), reading_history(JSON, ≤50 条, 新的在前), selected_sources(JSON, 空=全选), language, conversation_summary(TEXT)`

### 4.4 ChromaDB

集合内每条 = 一篇文章的向量（embedding：`paraphrase-multilingual-MiniLM-L12-v2`，384 维）+ metadata（source、Unix 时间戳）。
**索引只在采集时增补**，Agent 检索直接读，不按请求重建。

## 5. AI Agent

### 5.1 工具（`backend/agent/tools.py`，共 6 个，最多 5 轮）

| ID | 工具 | 输入 | 正常输出 | 降级行为 |
|---|---|---|---|---|
| AGT-1 | `search_articles` | query、sources?、days? | 语义检索结果（ChromaDB + SQLite 补 summary） | 命中空 → 关键词回退；空格无标点的专有名词（如 `owner/repo`）先走精确匹配 `_resolve_article` |
| AGT-2 | `get_article_detail` | article_id 或标题 | 单篇详情；顺带把它写入 `reading_history` | 传标题时回退精确标题匹配；找不到返回可读错误 |
| AGT-3 | `summarize_articles` | ids 或查询 | LLM 生成的摘要；顺带记录阅读历史 | LLM 不可用 → 返回原文摘要字段 |
| AGT-4 | `analyze_trend` | 时间窗/主题 | 语义检索 + LLM 热点归纳 | LLM 不可用 → 返回聚合统计 |
| AGT-5 | `trigger_collection` | 无 | 立即跑一次 `collect_once()` | 与按钮共用锁，不会并发 |
| AGT-6 | `web_search` | query | Tavily 实时结果（content 截断 500 字，过滤脏条目） | 未配 `TAVILY_API_KEY` / 网络失败 → 返回可读 error，不中断对话 |

### 5.2 System prompt 注入

日期锚点 + 数据边界规则（库里没有就说没有，别编）+ 用户兴趣 `interests` + 已读标题 `reading_history` + 历史摘要 `conversation_summary`。

### 5.3 前端渲染契约

`tool` 事件 → 徽章状态；`token` 事件 → 增量追加到当前气泡；`done` → 定稿并写入 `history`（供下一轮携带）；`error` → 若无占位则新建错误气泡，否则以引用块追加在已有文本后。

## 6. 关键实现流程

### FLOW-1 服务启动 → 首次自动采集

```
uvicorn 启动 → lifespan 执行
  → scheduler.start()（幂等）
      → asyncio.ensure_future(collect_once())  ← 启动即采一次
      → AsyncIOScheduler 每 COLLECTION_HOURS（6h）再跑
```

### FLOW-2 一次采集的内部步骤（`backend/scheduler.py::collect_once`）

```
① 读 user_profile.selected_sources（空=全部六源）
② NewsEngine.run()：asyncio.gather 并发抓六源（单源失败只记录，不中断）
③ 跨源去重：arxiv ID 指纹（arxiv ↔ pwc ↔ HN）
④ 排序：normalized_score × time_decay(48h 半衰期) × source_weight × quality_factor
⑤ LLM 相关性过滤 + 质量打分：judge_article() 单次调用返回 (相关, 质量分)，4 线程并发
      └ LLM 不可用 → 回退关键词过滤，quality=None（不阻塞入库）
⑥ save_articles(SQLite) → add_articles(ChromaDB) → 写 collection_runs（status=finished）
```

### FLOW-3 看板加载

```
DashboardLayout.onMounted
  ├ sourcesStore.fetchSources()  → GET /api/sources + GET /api/stats（并行）
  ├ articlesStore.fetchArticles()→ GET /api/articles?days=7&limit=50
  └ agentStore.loadInitial()     → 本地欢迎语（无请求）
```

### FLOW-4 筛选/排序链路

`days` 或 `sources` 变 → `watch` → 重新请求（后端筛选）→ 客户端再叠加 `search` 子串过滤与 `sort` 排序 → `paginated` 切 10 条/页。

### FLOW-5 Agent 对话（SSE）

```
前端 chatStream() ──fetch POST /api/agent/chat──▶ 路由
   ├ 读 profile（interests / reading_history→标题）
   ├ history>12 → summarize_conversation() 压缩进 conversation_summary
   └ chat_stream()：LLM stream=True
        ├ 有 tool_calls → 并发执行（最多 5 轮）→ yield tool start/done
        ├ 无 tool_calls → 逐 token yield
        └ 结束 → yield done(answer)
前端：ReadableStream 按 \n\n 切帧 → 分发回调 → 渲染徽章/增量文本
```

### FLOW-6 源开关持久化

`PUT /api/sources/{name}` → 校验 → 读 `selected_sources`（空按全选展开）→ 增删 → `_normalize`（等于全集则存 `[]`）→ `set_profile(selected_sources=...)` → 返回最新列表。

### FLOW-7 日报（GitHub Actions）

`.github/workflows/daily-report.yml` 每日定时跑 CLI `fetch` 生成 markdown 日报，与 Web 服务互不依赖。
