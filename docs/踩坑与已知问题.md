## 2. 外部服务限制

### 机器之心 RSS 免费额度 429

- **官方守则**：每个凭证**最多每 60 分钟 1 次、每日 25 次**，单次最多返回最近 10 条；超限返回 429，配额重置后恢复。
- **现状**：✅ 已实现 60 分钟退避（`RSSSource._backoff_active`）+ 429 后 6h 冷却（模块级 `_last_429_ts`，跨实例共享）。同日二次请求必 429（已实证），退避从源头避免。
- **影响**：退避/冷却期间 RSS 源返回空，其他源不受影响（优雅降级）。不是代码缺陷。

### 其他源的稳定性

HN 偶发 `ConnectError`、CSDN 偶发 521、GitHub 需代理——都在 `engine` 层被 `gather(return_exceptions=True)` 吞掉并记为 0 条，不阻塞整轮采集。

### 3.2 LLM 相关

| 问题 | 根因 | 修法 |
|---|---|---|
| 采集日志刷屏"LLM 判断输出无法解析"（#14） | `deepseek-v4-flash` 是**推理模型**：响应先出 `reasoning_content` 再出 JSON，`max_tokens=64` 被思考吃光 → content 为空或 JSON 截断 | `max_tokens` 64→256；`_chat_json` 把空串归一化为 None（静默降级，不刷日志） |
| 趋势/摘要工具连续失败（#15） | 同上但更严重：30 篇趋势任务 `reasoning_tokens=2048` 全被思考占满、`finish=length`、content 完全为空 | 工具 `max_tokens` 提到 4096；随后换非推理模型，底层问题消失 |
| 一次瞬时 5xx 就让工具失败 | `_execute_tool` 的"重试"只覆盖抛异常，工具返回 `{"error": ...}` 不触发重试；LLM 层当时无重试 | `_chat_json` 内置指数退避重试 2 次（1s/2s，4xx 参数错误不重试），所有 LLM 调用受益 |

**教训**：换模型先确认它是不是推理模型；短 JSON 任务的 token 预算要按"思考 + 答案"一起算。

## 4. 测试环境坑（2026-11-01 新增）

**happy-dom 不能用来测 DOMPurify。** 实测（dompurify 3.4.17 + happy-dom 20.x）：

- `sanitize('<script>alert(1)</script>ok')` 仍返回 `<script>`（没消毒）
- `sanitize('<ul><li>a</li></ul>')` 丢失 `<ul>`（误删）
- `afterSanitizeAttributes` 钩子只看到 `BODY`，遍历不到子节点

结论：happy-dom 的 DOM 遍历与 DOMPurify 的 `NodeIterator` 实现不兼容，用它测消毒会得到**假通过或假失败**。因此 `tests/frontend/components/MessageBubble.test.ts` 用文件头 `// @vitest-environment jsdom` 单独切到 jsdom，其余测试继续用 happy-dom（更快）。

**另一个坑**：测试文件在 `frontend/` 之外，裸依赖解析会失败——需要在 `vite.config.ts` 的 `resolve.alias` 里为「测试文件直接 import 的包」逐个指路（现有 `pinia`、`@vue/test-utils`、`dompurify`）。仅被 `src/` 内部 import 的依赖不受影响。
